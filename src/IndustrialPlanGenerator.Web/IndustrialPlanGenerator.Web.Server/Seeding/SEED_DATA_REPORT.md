## Verification Queries

```sql
-- Check users and roles
SELECT u.name, u.role, u.id
FROM users u
ORDER BY u.role;

-- Check shifts
SELECT * FROM shifts;

-- Check production lines
SELECT * FROM production_lines;

-- Check technician permissions
SELECT u.name AS technician, pl.name AS line, tl.permission
FROM technician_lines tl
JOIN users u ON u.id = tl.technician_id
JOIN production_lines pl ON pl.id = tl.line_id;

-- Check operator assignments
SELECT u.name AS operator, pl.name AS line
FROM operator_lines ol
JOIN users u ON u.id = ol.operator_id
JOIN production_lines pl ON pl.id = ol.line_id;
```

## Notes

1. **Fixed IDs** — All seed entities use deterministic GUIDs for consistency across environments
2. **Idempotent** — Seeder checks `AnyAsync()` before inserting; safe to run multiple times
3. **Navigation Properties** — Not populated in-memory after seeding; use `.Include()` when querying
4. **Development Only** — Seeder only runs when `ASPNETCORE_ENVIRONMENT=Development`
5. **Extensible** — Add maintenance domain seed data by extending `SeedAsync()` method

---

## Extending Seed Data

To add maintenance domain data (equipment, tasks, plans, etc.), extend `DatabaseSeeder.SeedAsync()`:

```csharp
// After SeedOperatorLinesAsync
await SeedEquipmentAsync(context, ct);
await SeedSensorsAsync(context, ct);
await SeedMaintenanceTasksAsync(context, ct);
await SeedMaintenancePlansAsync(context, ct);
await SeedPlanParametersAsync(context, ct);
await SeedPlanTasksAsync(context, ct);
await SeedPlanValidationsAsync(context, ct);
await SeedPlanAssignmentsAsync(context, ct);
await SeedTaskExecutionsAsync(context, ct);
await SeedReinspectionRequestsAsync(context, ct);
```

Each method should:
1. Check `AnyAsync()` first
2. Create entities with fixed GUIDs
3. Set all required FKs
4. Add to context
